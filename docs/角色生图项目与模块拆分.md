# 角色角色工坊库与模块拆分

2026-11-07

## 使用

打开「AI 生图」，默认准备软件目录旁的「角色工坊库」。其中包含公共素材、角色库、Temp、待删除和生图指引。已有旧版“生图项目”时继续兼容，不另行搬迁。公共素材中按姿势、场景、面部表情、配件、质量约束和原动漫脸型分目录。

在顶部角色工具栏点击「新建角色」，在弹窗输入名称并创建，即可得到素材来源的两个分类、参考图、图集、other，以及相对路径角色配置和外貌提示词模板。主脸等图片由后续生成与审核补充。

选定角色后，返回图保存在该角色的 other/待审核/渠道-任务标识 中。未选择角色时，保存到角色工坊库的 other/待审核/渠道-任务标识。渠道前缀为 api、codex 或 comfy，图片状态为待审核。ComfyUI 记录实际工作流；云端记录提示词分项、组合内容、提交内容、参考图顺序、用途、原路径与冻结副本及 SHA256。

可在「项目目录」菜单用「更换目录」关联已有项目根目录或角色库，用「使用软件旁的目录」恢复默认。默认目录按当前软件位置计算，随便携目录移动。自定义目录作为用户设置保留。

## 本轮模块边界

- Rust 的 character_workspace.rs 负责项目和角色目录约定、名称校验、角色发现及候选目录分配。
- commands/character_workspace.rs 负责桌面命令、软件位置和用户设置。
- CharacterWorkspacePanel.tsx 负责角色建档、选择和反馈。
- GenerationTrainingSection.tsx 从 GenerationPage.tsx 提取训练集导出与训练衔接，沿用共享操作忙碌状态。
- ComfyUI 下载入口接入候选目录分配，按任务隔离文件，并保存实际工作流。
- GenerationPage.tsx 仅保留公共角色选择、两个页签及忙碌状态协调，从千余行缩减到 51 行。
- CloudGenerationPanel.tsx 负责云端表单与请求，CloudChannelSettings.tsx、GenerationReferences.tsx、GenerationPreview.tsx 分别管理渠道、参考图与预览。
- ComfyGenerationPanel.tsx 承接原有 ComfyUI 工作流和参数，使用动态加载，首次进入本地页签才加载。切换页签保留两个表单。
- GenerationSettingsPanels.tsx 从 SettingsPage.tsx 提取 ComfyUI 和 LoRA 训练设置，减少设置页面约 420 行。
- Rust cloud/profiles.rs 负责渠道配置，credentials.rs 负责 Windows DPAPI，api.rs 负责 HTTP 生图，codex.rs 负责本机 Codex app-server 通信；commands/cloud.rs 只负责 IPC、项目落盘与任务状态协调。

重名创建返回明确错误。目录初始化失败时仅回收本次创建的空目录和文件，已有角色由列表打开。候选图片仍须审核后按项目规则命名入库。

## 后续重构边界

代码较集中之处仍包括 SettingsPage.tsx 的识别模型设置、安装和下载，ComfyGenerationPanel.tsx 的工作流与快捷参数，以及部分 Rust 命令中的长流程。当前拆分先建立明确边界，并未宣称全部重构完成。

后续按设置分组、工作流参数编辑、审核与资产版本等职责逐项提取。现有协议、角色标注、训练和目录兼容行为应有对应回归验证。Agent 对话和跨图库统一返修队列仍使用原工作台。当前已接入本次生图批次的待审核、已通过和待返修操作，不等同于跨图库审核系统。

## API 与订阅使用

默认打开「API / 订阅生图」。提示词按角色与衣装、姿势动作、表情、场景、镜头与构图、质量约束分别编写，也可复制组合后的提示词。参考图可从本机选择或填写完整路径，支持排序、移除与用途说明；发送实际图片内容，每次最多 8 张，单张 25 MiB、总计 64 MiB。

API 渠道可新增、编辑名称、Base URL、模型、协议及 Key。Base URL 通常包括 /v1。兼容 OpenAI Images 时，无参考图使用 /images/generations，有参考图使用 /images/edits 的 multipart image[]；Grok JSON 参考图协议使用 JSON images/data URL。服务商需支持所选协议，模型名由用户填写。不会自动在第三方服务之间切换或重试。返回支持 b64_json、图片 URL 和 data URL；服务商错误及缺少图片均会直接显示。代理沿用基础配置。

Key 使用当前 Windows 用户的 DPAPI 加密后保存到便携数据库，不在列表和请求记录中返回明文。备份复制到不同 Windows 用户后需重新填写 Key。

订阅目前接入本机 Codex，自动寻找 CODEX_HOME 或用户目录 .codex，显示 config.toml/auth.json 是否存在，并通过本机 CLI 的 account/read 获取实际登录账号和套餐。需要已安装且登录的 Codex CLI，配置文件存在不作为生图成功凭证。登录和令牌管理由 Codex 执行；不读取令牌再冒充 API Key 发送给第三方。订阅的尺寸、质量通过提示词表达，实际尺寸以工具返回为准。

Codex 使用本机 app-server，通过临时任务提交提示词与本地图像；图片回收须为本次可验证产物。整个请求使用异步调用和独立超时，界面显示等待状态。当前一次执行一个云端任务，未提供主动取消按钮。账号识别成功不保证所有机器均开放图像工具；未返回图像时显示具体原因。

候选落到待审核目录，尚不自动覆盖图集原图或为角色永久主脸。备份除数据库外，还需备份角色工坊库；默认项目随软件位置计算，自定义目录保持用户设置。

## 标准资源、批次与审核

资源索引从用户选定的工坊库权威文档按需读取。角色身份与衣装拆开，姿势使用稳定 ID，场景以独立空间 ID 绑定四个方向。参考路径以所属资源目录或库根为基准解析；队列冻结输入文件并记录 SHA256。集合目录不作为单人角色选项，缺配置、缺图及哈希变化显示为明确问题。

GenerationResourceControls.tsx 负责造型、姿势和场景树形选择及预检；generation-catalog.ts 负责总量、每姿势、兼容组合和有种子的随机展开；resource-prompts.ts 保存本次会话按资源区分的提示词改稿，支持恢复库版本。改稿需要跨重启保留时，先建立批次。

GenerationBatchDialog.tsx 和 generation-batch.ts 负责逐项查看、未执行项改稿、串行运行、暂停和审核；Rust generation_batch.rs 与对应 commands 模块负责持久化、参考快照、迁移后恢复、状态判断及审核命名入库。新图默认待审核，返修原因不能为空，审核通过才采用到图集。运行中断且结果不明确时不会自动重新发起收费请求。

当前已验证三种数量模式、随机候选和保存种子、模块改稿恢复、单任务改稿不影响其他项、实际 EXE 的参考图二进制上传、重启续跑及审核入库；另通过一次携带身份、衣装、灰模和场景四张参考的真实订阅角色生图。网络模拟检查和真实模型检查分别记录。场景布局及人体质量仍需逐图审核；未经核定的支撑条件不会强行配对。
