# 角色工坊融合实施方案

2026-10-08，设计阶段。目标是可持续迭代的单一桌面软件；当前尚未完成合并程序。

## 1. 产品闭环

角色身份与衣装参考 → 规划角色/姿势/场景/表情 → 云端或 ComfyUI 生成 → 技术检查和视觉审核 → 候选返修 → 人工确认入库 → 相似图治理和多样性筛选 → 训练集 → LoRA 训练 → 固定种子/保留集评估 → 再生成。

手动与 Agent 共用这条流程，区别在谁提出配置和谁执行下一步。没有视觉能力时只返回待审核候选。成功收到图片不等于质量通过。

## 2. 技术决策

采用 anime-pic-manage 的 React/TypeScript + Tauri/Rust 作为唯一界面和宿主，保留其 Python 本地推理 Worker、ComfyUI 客户端和训练器控制。把现有 Agent/API/质量服务从 Qt 分离为另一个轻量 Python Worker，使用版本化 JSON Lines 协议；后续再逐项收敛到共享服务。不要在第一步要求 ONNX、训练器、云端 SDK 和 PySide 全部装在同一个环境。

```text
React 桌面 UI（项目、聊天、手动生成、图库、审核、去重、训练）
                ↓ Tauri commands / events
Rust Core（资源索引、路径检查、凭据、任务、取消、文件操作、调度）
        ├─ Local Analysis Worker：检测、识别、参考匹配、相似度、打标
        ├─ Agent / Cloud Worker：经验检索、规划、API生图、视觉审核、返修
        ├─ ComfyUI Adapter：工作流、节点、上传参考、任务与成图
        └─ Training Adapter：kohya / sd-scripts 环境与进程
```

**写入所有权**：Rust/AssetService 负责统一图片版本与文件操作；每个 Worker 可以写自身任务工作目录，不能直接改正式图库或另一方 SQLite。每个数据库只由所属服务迁移。首期通过 ID 映射和事件接口桥接，不直接把两个来源数据库的表追加到一起。

**项目上下文**：Worker 启动固定一个 project_id/root，切换项目不修改正在执行任务的全局路径。记录引用 ID 和快照；旧图片路径变化不改变资产身份。

## 3. UI 与工作模式

- 项目导航与新聊天：项目下聊天/任务，角色是项目资源。
- 生图工作台：手动/Agent；云端/本地；角色、姿势、场景、表情、参考、质量约束；大预览。
- 角色与图库：身份、衣装版本、原作/游戏/真人衣着/真人身份参考，图库及来源关系。
- 审核返修：待审核、待返修、已通过；原图和候选对照、区域放大、蒙版确认、人工决策。
- 相似图治理：精确重复、近似图片、构图近似、身份相似分组；先预览计划再归档。
- 训练中心：生成 LoRA 与角色识别学习分开，训练集、训练版本、评估和安装。
- 知识与经验：姿势/场景/表情/质量约束/角色标准、来源、版本、实际请求。
- 设置：云端/规划/视觉模型、本地引擎、存储、代理、预算、GPU、备份。

保留用户既定体验：窄导航、交界拖动、适应宽度、无横向滚动条、勾选有勾、巨大预览/全屏、备选和复杂编辑用超大弹窗、错误可见。角色正式目录只留图片与 other，参考目录相同。

## 4. 提示词与引擎适配

统一内部结构：identity + costume + pose + scene + expression + camera + constraints + repair + references。保存每个片段来源与原文、组合后的最终文本、提交给引擎的实际参数、模板/模型/LoRA/hash/seed。

云端 Images/Grok：按协议提交最终提示词、真实图像内容和受支持参数；质量排除条件写进文本，不假设有独立 negative_prompt。

ComfyUI：将身份/姿势等模块编译到 positive；排除标签编译到 negative，依据底模和编码器长度作警告，保留完整模块原文。必须有完整工作流映射；参考图通过已声明 IPAdapter/ControlNet/LoadImage 等节点上传绑定，不能把磁盘路径当成远程图片。蒙版仅在声明对应节点与尺寸的工作流可用。高级节点覆盖值须显示哪些模块被覆盖，不能静默忽略。

本地工作流至少分文生图、参考身份、姿势控制、局部返修四种能力清单。ComfyUI 在线不代表所有模板都能参考或返修。接口能力不支持则显式拒绝；切引擎/重试由可见计划控制。

## 5. 识别与质量

动漫检测/CCIP 原有能力复用，但对真人域的适用性要用用户角色图库建立评估集。identity_id 与 costume_variant_id 分开，小南不同衣装共享角色身份；coser_identity_id 可跨衣装共享，也可重新选择演员脸。原著动漫和衣装照不自动作为真人脸模板。

身份参考匹配只能提供相似建议。人体结构、手指脚趾、丝袜包裹/拇趾分区、纸翼背部连接和随身体旋转、衣装连续性等使用结构化视觉观察及裁切证据；遮挡或分辨率不足时为不确定。图片审核状态单独保存，不用识别置信度替代。

禁止自动以一个相似度阈值删除图片。真人身份和不同姿势可能导致通用向量混淆；分别展示分数来源和比较对象。

## 6. 训练闭环

生成 LoRA：默认只采用已通过、人工确认身份的版本；去重、姿势/角度覆盖、caption 编辑；身份触发词与衣装触发词可分开。训练集冻结包含内容哈希、许可来源说明、caption 与模型家族。训练产物记录底模哈希、参数、训练集版本及日志。

个人识别学习：复用质心/校准路线，UI 明确这是识别学习；不能包装成 LoRA。评估需按原图/生成来源分组防止同图变体混入训练与验证，动漫与真人域分别报告。

LoRA 回测：同底模固定种子、强度、多个未见姿势/场景；人工检查身份与结构，记录优劣。不能承诺换任意底模都达到同一效果。

## 7. 任务与资源

task_id 关联 chat、asset、generation、review、repair、dataset、training、evaluation。进度区分已请求/已返回/已审核/已通过/需返修/未知。训练与 ComfyUI 默认 GPU 互斥，本地识别可排队；CPU 工作与云端任务可独立执行。

远端失败分为明确拒绝、参数错误、连接未发出、返回失败、超时结果未知。未知请求先尝试查询或人工确认，禁止无提示再扣费。取消停止后续步骤；能否中止当前远端请求和本地任务分别展示。金额预算按用户设置单价估算+服务返回实际用量；缺价则未知，不能写成 0 元。

## 8. 迁移

先只读清单，记录两个旧库、文件/引用、路径和哈希；默认关联原目录而非拷贝全部图片。映射角色同名/别名、ID、衣装和演员身份，冲突需确认。迁移前生成在线数据库备份；在新库写入 mapping/版本记录，逐项校验后再切换。

旧 API/DPAPI 密钥留在本机并单独导入，不进 Git/ZIP；新界面不会复制 Codex auth 文件。状态原值及来源保留，未知旧标签进入待审核；正式图片文件名按用户既定规则，首次导入不自动批量改名。相同字节可有多个版本关系，避免用内容哈希当唯一业务 ID。

迁移验收：每个 asset 可追溯原路径；候选/原图/请求/审核关联不丢；旧应用仍可启动；所有改名覆盖操作有原图归档与日志。双应用同时写同一图库时需要排他锁。

## 9. 分阶段交付与验收

| 阶段 | 工作 | 必须可演示的结果 |
|---|---|---|
| M0 当前 | 源码审计、领域协议、界面概念、验证基线 | 两端已有/缺失能力明确，UI图与计划可查看 |
| M1 桌面骨架 | 新工程、统一导航/项目/资源 ID、只读旧库导入、Agent Worker health | 一个窗口查看同一角色的两端资料；原库不改；环境不齐仍能开 UI |
| M2 双引擎手动生图 | API 与 ComfyUI 适配、工作流能力、实际参数/参考快照、统一候选 | 同一角色分别云端/本地出图，均为待审核，错误/取消可见 |
| M3 审核与返修 | 视觉适配、规则、区域裁切、蒙版、关联候选、人工入库 | 修复手/脚的前后可比较；不支持的引擎提前阻止；入库可恢复 |
| M4 Agent | 经验检索、计划确认、工具、预算、批次、恢复 | 一段要求执行少量生成/检查/返修，停机恢复不会重发未知请求 |
| M5 识别与相似 | 原本地流程接入统一资源；真人域基准与人工反馈 | 同图识别/去重/审核互通，但分数与状态不混淆 |
| M6 训练闭环 | 数据集版本、caption、训练、资源调度、固定种子回测 | 从通过图库冻结训练集、训练并安装 LoRA、生成对照并记版本 |
| M7 发布 | 全范围备份、迁移恢复、打包/更新、安装/便携、真实样本验收 | 新软件可安装，原数据恢复无误，未配置模型也能使用基础图库 |

每一阶段都要交付可运行版本和真实小样验收，不积累到最后才打包。M2 的图像输出和 M3 的人体判断必须由真实请求检验，离线测试只能验证软件逻辑。UI 图片只是概念，不是功能已实现的证据。

## 10. 完成定义

既支持本地生成又支持云端/Agent 流程；手动与 Agent 不维护两份状态；生成来源可复现；人工审核能覆盖模型建议；返修不丢原图；训练/识别/相似度用同一版本资源；数据迁移可回滚；费用与未知结果可解释；完整 Windows 应用稳定启动和关闭。模型审美与人体判断不承诺完美，需要可核验的建议和人工复查。
