# 真人 cosplay 生图经验

更新日期：2026-10-08。适用范围：本项目的成年角色真人 cosplay 参考图、普通写真、自拍、休闲旅游、地铁随拍、水中与带纸翼成图，以及局部返修。

这份文档依据本项目实际提示词、参考图、训练记录、接口返回和逐图复核整理。文中的“已观察到”是本项目的结果；“建议”是下一次可以采用的方法，不代表已做过严格对照实验。接口名称、价格和行为只描述记录时的状态，不当作长期服务承诺。

## 1. 最有用的经验

让图片像真人 cosplay，需要同时解决四件事：同一个人的脸、同一套角色衣装、可信的摄影与材料、正确且符合目标的身体动作。画面清晰或漂亮，只解决其中很小一部分。

本项目比较有效的工作方式是：先确定用户认可的唯一主脸，建立少量有明确用途的参考图，再把身份、衣装、动作、表情、场景、机位和质量要求分开组织。每次只上传目标需要的参考，并说明每张图负责什么。生成以后先看整体，再检查手脚和衣装细节，通过后才成为正式图或下一次的参考。

不要把某次顺利成图归因于一个“神奇关键词”。本项目还没有证明英文一定优于中文、参考图越多越好、quality 档一定更强，或某种颗粒能稳定消除 AI 感。

## 2. 从原作角色到真人 coser：分别解决身份和衣装

### 2.1 三类输入的分工

| 输入 | 用来确定什么 | 不直接继承什么 |
|---|---|---|
| 原动漫脸部图 | 角色的发型、眼型倾向、神态、标志性面部装饰 | 动漫的夸张眼球比例、平面鼻子、画线睫毛与不存在的真人骨骼结构 |
| 手游立绘与建模截图 | 当前皮肤的衣装剪裁、颜色、配饰、鞋型、纸翼与道具 | 低清锯齿、贴图瑕疵、建模关节变形，以及看不清的细节猜测 |
| 真人 cosplay 照片 | 面料、缝线、做工、佩戴方式、妆造与真实光照 | 对方的完整面孔和身份；除非任务明确要求，否则不将其当作脸部锚点 |

用户已经决定小南的不同衣装应采用同一张 coser 脸。执行上应共享身份锚点，同时分别维护白鹤、神驹、泳装等服装参考；不能每换衣装就重新创造一位模特。这是后续应遵循的身份规则，不表示所有历史图已经完成统一。

### 2.2 用户确认优先于模糊截图推断

泳装小南鞋履曾先后被理解为较低凉鞋、较高鞋跟、包脚鞋面，最后用户确认的是紫色鞋底与独立粗跟、前脚背横向白色宽带。应保留这个校准过程的来源，但后续只使用最新通过版本。

同样，角色名或文字介绍中的“泳装”“比基尼”不能替代当前实际衣装结构。泳装小南本项目当前认可参考04展示的是白色高领挂脖连体款、水滴形胸前开口。生成时应保留该输入，不能因为泛称而自行改成分体款，也不能把项目参考直接宣称为未经核实的官方精确设定。

低清图中没有辨清的扣件、接缝或背带，应写成“待确认”。不能让生成模型的补全反过来成为所谓原作依据。

## 3. 脸部一致性：先固定一个人，再变化表情和角度

### 3.1 唯一主脸

泳装小南当前身份锚点是：

`角色特征及参考图/泳装小南/泳装小南_参考01_身份主脸_正面.png`

其记录的 SHA256 为：

`052762934c6f08d9bd65d8d87a6a125b79b10393d960b69fa8c2bf2569a68c0c`

这张来自用户已经认可的成年中国女性虚构 coser 图。后续是让同一张脸转头、微笑、换机位，不是每次重新生成一位“更漂亮的人”。用户未采用的偏欧美、偏成熟版本不能继续混入主脸参考。

主脸需要检查眼距、眼型、鼻唇比例、下颌、脸部纵横比例和年龄观感；紫发、瞳色和纸花相同，不足以证明是同一人。也不能用更浓的妆或更大的眼睛掩盖换脸。

### 3.2 适合本项目的描述

```text
Preserve the same fictional adult Chinese cosplayer from the identity reference, with the same facial proportions, eye spacing, nose and lip shape, jawline and adult age appearance. Change only the requested expression and head direction; do not replace her with a different model.
```

中文注释：以主脸保持同一位成年中国女性虚构 coser，固定面部比例、眼距、鼻唇和下颌；仅改变要求的表情及头部方向，不换模特。

“中国成年女性”是本组真人化的目标描述，不代替具体脸部参考。比起堆叠国籍或泛化审美词，更重要的是与用户认可的那张脸逐项比较。

### 3.3 侧脸和笑容不是重新捏脸

正面、四分之三、纯侧面应保持鼻尖至下巴的轮廓关系。严格侧面允许远侧眼睛隐藏，不能为了让两只眼睛都可见而把脸扭回正面。

笑容需要眼睑、脸颊和嘴角一起变化，而不是只把嘴拉宽；牙齿不要变成均匀发光的白板，下唇钉应随嘴唇移动。建议用平静、闭口微笑、略露上牙的轻笑、坚定等少量清楚的表情方向，不同时要求冷漠、热情大笑、害羞等互相竞争的表情。

表情三联图只用于表情对照。应注明最终输出仍是单人单幅，不继承三联排版或生成三个相同人物。

## 4. 建立参考图套组，而不是无限堆图

### 4.1 本项目已采用的基础八张

| 编号 | 内容 | 用途 |
|---|---|---|
| 01 | 身份主脸，正面 | 唯一脸部锚点 |
| 02 | 身份侧脸，四分之三 | 转头、回望和半侧脸 |
| 03 | 身份侧脸，纯侧面 | 鼻唇与下颌侧轮廓 |
| 04 | 衣装全身，正面 | 正面剪裁、体型比例、基础鞋型 |
| 05 | 衣装全身，背面 | 背部开口、连接带、后发与鞋跟 |
| 06 | 纸翼结构，背面半身 | 翼根、长弧、纸材和完整双翼，不冒充全身图 |
| 07 | 鞋履细节，自然站立 | 前脚背横带、紫底独立粗跟、足部连接 |
| 08 | 面部表情，三联 | 同脸的不同表情，不继承多格布局 |

纸翼后来增加09纯侧面、10三分之四背面、11纯侧面前倾、12三分之四正面，用来处理视角与背部方向；它们不是要求每次全部上传。

八张基础加四张翼部扩展是本角色当前的组织方案，不是“十二张就能保证任意生成完美”的结论。极端透视、复杂手部接触、镜面、遮挡和腾空仍可能失败。新增参考应解决一个现有套组没有说明的问题，不靠增加相似正脸凑数量。

### 4.2 按目标选参考

| 目标 | 起始组合 | 必要时补充 |
|---|---|---|
| 正面近景 | 01 | 需要看见泳装时加04；明确表情时加08 |
| 四分之三近景 | 01、02 | 衣装可见则加对应衣装图 |
| 纯侧脸 | 01、03 | 不强迫远侧眼露出 |
| 正面全身、坐姿、行走 | 04、01 | 鞋很重要时加07 |
| 背面、背身回望 | 05、01 | 需要时加02，不能用04推断背带 |
| 带纸翼 | 主脸、对应衣装、最相关翼部参考 | 需要游戏轮廓时选游戏图，避免重复上传所有翼部角度 |
| 水中 | 主脸、衣装 | 不强迫上传或展示被水遮挡的足部 |
| 指定动漫动作 | 主脸、衣装、动作示例 | 动作图只负责肢体，不继承其中人物和服装 |

上述组合是起点，不是接口保证。参考数量还要服从当前工具实际支持的输入和本次调用结果，不能照搬旧文档中的数量上限。

### 4.3 每张参考都写明用途

```text
Image 1 defines the outfit, hairstyle and footwear only. Image 2 is the identity reference for the face. Do not copy the reference background or standing pose. All images show the same person and the same accessories from different views; do not duplicate them.
```

中文注释：参考1只控制衣装、发型和鞋履，参考2控制脸；不迁移背景与原站姿；多视图表示同一个人与同一件配饰，不累加配饰数量。

脸部优先级应由用途说明确定，不能声称图片排第一就必然获得某种固定权重。本项目Grok成功请求常用04在前、01在后，这不表示其他排列必然失败。

### 4.4 不合格图不能继续当标准

待返修、多指、错误袜料、旧短扇翼、错误鞋型或身份漂移的图，不应该因为“文件仍在正式目录”就被再次引用。选择输入时读取最新标签和复核记录。用户指定的合格主脸与标准裁切要保留原字节；替换标准时建立版本记录。

## 5. 提示词模块：分开写，合并后检查

建议在工作台保留以下独立字段：

1. 人物身份：成年观感、同一主脸、角色发型、眼妆和面部标记。
2. 衣装与配饰：剪裁、覆盖、颜色、材质、鞋型与配饰数量。
3. 姿势：身体方向、头部、左右手脚、支撑、接触位置与视线。
4. 表情：一种明确的表情方向。
5. 场景：背景、承托物、空间与光源环境。
6. 机位与构图：拍摄方向、取景范围、需要完整展示的部件。
7. 适用质量约束：通用人体，加本角色需要的袜料、鞋履或纸翼模块。
8. 参考用途：每张输入控制什么，不控制什么。

“完整提示词”是以上实际模块组合后的请求正文，应能在发送前预览和复制；它不应在发送时悄悄换成另一套措辞。模块和最终原文都保存，才能知道错误来自哪里。

遵循本目录AGENTS规则：姿势库正文只写肢体、承重与视线，场景放场景库。沙发、床、窗台等承托物需要在组合时明确选定，不能在姿势模块写床、场景模块又写沙发。机位段也不能夹带另一个动作。

### 5.1 提示词不是越长越好

通用模块只放各角色都适用的要求。“侧卧时肘在肩下”“内八时髋膝踝协调”“白丝袜包住脚趾”只能在对应任务启用。把所有历史修复规则全加进每一张图，会产生新的冲突。

不要同时要求叉腰和手扶大腿、普通站姿和坐垫支肘、背面不回头和眼睛直视镜头、很宽足距和强迫双膝相碰。优先修正文义冲突，再追加质量词。

### 5.2 中英文必须表达同一个目标

本项目实际遇到：

- 第2条中文要求双腿“向前伸展”，英文只有并腿和轻弯，没有写伸展。
- 第23条英文“朝膝盖方向”没有明确手掌要接触膝盖外侧。
- 第24条英文只写一手支撑，遗漏中文的“身前”；同时出现床与沙发冲突。
- “下腰站立”的动作正文实际是从髋部前倾，不是向后体操下腰。

遇到这些偏差，不能把责任全部归为模型不听话。应保存实际发送的英文，再核对它是否真的包含中文目标。后续优化版不能冒充旧图的原始提示词。

## 6. 一段完整的普通真人 cosplay 提示词示例

以下是可复用模板，不冒充某张历史图片逐字使用的原文。参考顺序为04衣装、01主脸。

```text
Create one realistic photograph of the same fictional adult Chinese cosplayer, age 26. Image 1 defines her white halter one-piece swimsuit, purple hairstyle and footwear. Image 2 defines her face. Preserve the same facial proportions and adult identity.

Preserve the exact opaque swimsuit construction, its geometric collar pieces and original front opening. Keep exactly one lavender paper rose on her anatomical right side and the small lower-lip stud. Preserve sandals with one broad transverse white forefoot band, purple soles and separate chunky heels, without added instep or ankle straps.

Pose: stand with comfortable weight on one leg, both arms relaxed beside the body and fingers naturally curved. Turn the head slightly toward the camera with a gentle closed-mouth smile.

Scene: an open seaside resort terrace with soft daylight and a quiet distant background.

Composition: natural camera perspective, full body and both sandals in frame. Keep the face readable and the background subordinate to the subject. No wings for this image.

Quality: natural fine skin texture, believable fabric tension and seams, coherent lighting and contact shadows. Exactly two arms and two legs with connected joints; natural finger overlap and occlusion are allowed. Do not copy the reference pose or studio background, duplicate accessories, add plastic smoothing or excessive grain. One person, one photograph, no collage or text.
```

中文注释：同一26岁成年中国女性coser，参考1锁衣装、发型和鞋，参考2锁脸；白色不透明连体泳装保持剪裁，右侧只有一朵纸花，鞋只有单道白色横带和紫底独立粗跟。单腿轻承重、双臂自然下垂、轻转头闭口微笑；海边露台、柔和日光、全身含鞋、无翼。保留真实皮肤与衣料，关节和接触自然，允许遮挡，不复制参考的背景和原姿势，不加重颗粒和塑料磨皮。

替换时主要更换姿势、表情、场景和构图；不要每次重写身份，或把已确认鞋型改回模糊的“白色凉鞋”。

## 7. 减少 AI 感：本项目真正要检查的内容

### 7.1 已观察到的问题

本项目Grok同条件样本即使已跟随紫发、纸花、唇钉和衣装，人脸仍可能变圆、变柔，皮肤过于平滑，衣料高光偏强。这说明角色相似与摄影真实感是不同维度。

用户明确不喜欢重颗粒。后续提示词一直优先柔和光照、自然细微肤质与面料纹理，没有把强颗粒当作必选手段；目前没有做过“加多少颗粒最好”的控制实验。

### 7.2 实用检查方向

- 光：脸、手、腿、道具和背景应该能由同一组光源解释。阴影方向和软硬程度协调，不让所有表面都发出同样的亮边。
- 皮肤：保留细微纹理和自然明暗变化，避免均匀蜡感；不以夸大毛孔、皱纹或噪点替代真实肤质。
- 妆造：假发可以有真实发丝与整理痕迹，妆面可精致，但不能把所有发丝、眼影和嘴唇画成没有层次的塑料表面。
- 衣料：剪裁、接缝、张力、褶皱和高光应配合身体和材质；白色弹性织物、薄纸、尼龙、金属与皮肤不能共用一种光泽。
- 镜头：人物透视、景深和背景清晰度协调。不要用过度虚化隐藏所有问题，也不要要求每根远处脚趾都同样锐利。
- 表情：眼睛、面颊和嘴角一起变化，减少批量图片完全相同的面孔与凝视。
- 场景：根据服装与动作选自然适配的环境，保留生活空间和接触关系；背景变化不能只换一张模糊贴图。

这些是下一次提示词和验收的方向，不是已经验证的固定相机公式。没有实测某个焦距或光圈时，不需要为了显得专业而堆相机型号、8K、HDR、极致毛孔等词。

## 8. 衣装、配饰和鞋履：小改动也可能破坏一致性

### 8.1 面孔和衣装都需要输入

泳装小南近景曾只引用主脸，生成结果把泳装错误延伸成封闭白色上衣。即使只拍头肩，只要能看到领口和胸前结构，也应提供或清楚描述衣装；“保持白色高领”不等于保持整个剪裁。

背面衣装以05为准。纸翼参考06中被翼根遮住的背带不能拿来猜完整结构。修纸翼时曾把原分岔连接带改成直带接水平腰缘，之后需要按05单独恢复。

### 8.2 多视图会复制配饰

Grok带翼对照中，主脸和衣装都带纸花，结果画出两朵：一朵在鬓角，一朵在后脑发髻。应明确这是同一朵花的不同角度，角色右侧一朵即可，因视角隐藏时允许不出现。

手持折纸鹤也曾被误当作胸针。参考中的道具与衣装有重叠时，要指出它是拿在手里的物体；目标没有要求就不自动增加胸前纸鹤。

### 8.3 单道鞋带的约束不保证生效

泳装小南当前标准是：前脚背一道横向宽白带，紫色鞋底与独立粗跟，不增加踝带、踝扣、第二道脚背带或后跟包带。横向指跨越脚的左右两侧，画面透视可以让它看起来倾斜。

两张Grok带翼图各返修三次，仍没有完整去掉额外鞋带。加入07鞋履参考也没有保证成功；后续候选还出现纸花复发、领口变化或双脚移位。因此不能把“已写 no second band”当作通过证据。

## 9. 人体与动作：分两张检查表

### 9.1 人体结构

先沿连接链检查：肩—上臂—肘—前臂—腕—手，髋—大腿—膝—小腿—踝—脚。观察每条链属于谁，有没有额外分叉、断开、重复关节或穿过物体。不要只数露出的皮肤块。

夏日黑土030酒店座椅图曾在下半部多出一段腿脚。错误判定需要对应用户指出的原图、实际版本和具体位置，不能拿另一张正常图返修，也不能只裁掉问题区域就宣称结构已修好。

正常遮挡不等于缺肢。手在另一只手后面、腿被裙摆遮住、脚在水下时，应写“不可核验”或“自然遮挡”，不强迫补出本来不该出现的肢体。

### 9.2 目标动作

两臂两腿都正确，仍可能姿势不对。近期Grok常把侧卧生成侧坐，把仰躺生成靠坐，把一腿伸直另一腿弯曲生成双腿都折叠。它们可以是漂亮写真，但不能当作指定姿势已实现。

审核应分别记录“人体数量与连接”“动作匹配”“身份”“衣装”“道具与构图”。这是本项目严格通过率较低的原因之一，不能把所有待返修都解释成人体畸形。

### 9.3 复杂动作减少重复几何命令

内八腿需要从髋、膝到脚协调，保留用户要求的轻度内扣与腿间小空间；不能擅自改成普通站距，也不能通过膝部横折或翻转脚踝凑内八。

过去提示词叠加固定宽足距、极近膝距和大腿贴近等要求，同时通用模块又夹带侧卧支肘，存在明显竞争。这是提示词与成图对照得出的风险推断，不是已证明每张畸形都由某一词引起。

回眸侧卧也要区分身体与相机：骨盆和大腿方向连续，脊柱自然，只作合理转头和肩腰转动；必要时调整机位，但不能用极端扭颈扭腰表现回眸。

## 10. 手指检查与接触描述

每手的完整结构是一拇指、四手指，但不要求每张图都露出五个指尖。应看指根、指节、掌心方向和前臂连接，不是把五个分叉凑齐。

重点动作：

- 扶帽：手指自然接触帽檐，帽檐与手掌不互相穿透，指根和腕部连续。
- 指向远方：食指伸出，其他手指自然屈曲，拇指位置符合该手旋转；不额外长出一根“指向线”。
- 握手机：区分拇指与绕到背面的手指，手机遮挡部分手掌是正常情况；镜像需整体一致。
- 扶栏、撑面、支肘：明确哪只手或前臂接触哪个表面，是身前还是身后，不能只有模糊的“一手支撑”。
- 两手交叠：先沿两条手腕分别找到自己的掌，避免融合成一只多指手。

通用英文模块已有 `质量约束nagetive/通用人体与手指.txt`。使用它仍需要放大检查。不要给所有动作都追加“手指完全展开”，这会破坏握持、托头与交叠的动作。

## 11. 左右脚、脚趾与白鹤白丝袜

### 11.1 左右归属由腿决定

沿髋、膝、踝追到足部，再判断脚的旋转和大拇趾内侧位置。交腿、侧卧、仰视和镜像都会改变脚在画面中的位置，不能用画面左边就是左脚的方式判断。

夏日黑土曾出现两脚趾排列互换。返修时需要同时看各脚轴线、鞋头和鞋跟方向、拇趾分布与踝部连接，不能只在一小块脚尖上重画五个指甲。

### 11.2 白鹤标准不是“把裸脚涂白”

标准材料示例是 `质量约束nagetive/白鹤白丝-标准足部.png`，来源对应用户指定的标准坐姿足部裁切，具体来源和哈希见该目录的来源索引。

袜料应是连续、贴合的闭口细尼龙，包住脚背、足底、脚跟、全部脚趾与趾甲，有细密织纹、柔和丝光、张力和自然体积。不能画成露出裸趾、近乎透明的白脚、棉袜、五趾袜或一个抹平的鼓包。

红色Y形夹脚带允许自然压痕。拇趾单独占一侧，其余四趾在另一侧，由同一层连续袜料统一包裹。四小趾之间只允许短、浅、柔、低对比的轮廓，不能形成深长黑沟或每趾独立袜套。包裹感与合理浅压痕可以同时存在。

“五个脚趾清晰分开”与这个材料目标可能冲突。正确数量不等于必须透过袜子把每条趾缝刻出来。

上传标准裁切时说明它只控制袜料和Y柱关系，不复制坐姿、背景或裁切构图。老超分接口曾只返回标准脚部的放大图；收到清晰脚部图片也不能算完成完整人物返修。

完整英文材料约束见 `质量约束nagetive/白鹤白丝袜与Y形鞋.txt`。它只给对应白丝袜角色使用，不给泳装小南裸足加袜子。

## 12. 自拍、地铁、旅行与水中照片

### 12.1 自拍

区分直接自拍和镜前反射。镜前图需要明确最终画面是镜像，检查手机、持机手、纸花佩戴侧和整体姿态是否一致。不能只翻转某个配饰。

纸花实际佩戴在人物右侧；直接正面照通常出现在画面左侧，镜像又不同。若有后续整图翻转应记录，不能擅自猜测平台已经翻转。

全身镜需要真的容纳头脚与动作。参考图的站姿不应让目标跪姿消失，也不能把要求的全身图自动裁成半身。

### 12.2 地铁与旅行

地铁抓拍可使用自然不看镜头、车门扶杆的空间线条、顶灯和轻微生活构图；不要把“抓拍感”简化成重颗粒和模糊人脸。坐姿要与座椅接触，持杆手要有真实握持。

旅行图应改变实际活动、身体朝向、机位和空间关系，而不只替换背景。交通工具座椅、窗、扶手与人物比例要合理，别把酒店沙发直接贴进车厢。

狭窄车厢不强迫展开巨大纸翼。宽阔镜前或室外可按目标使用纸翼，但必须留够空间。

### 12.3 水中

水线上下是同一组肢体。折射可以造成轻微位置变化，不能变成第二套膝盖、小腿和脚。浅水站姿的足部应真正接触合理池底，踏阶需要与台阶及扶杆接触，漂浮需要躯干、骨盆和腿的方向连续。

水面倒影、浪花和反光不能画成新的实体肢体。不强迫展示应被水遮住的脚。泳装保持不透明，不因为水中场景增加透视材质；纸翼是否出现由目标和空间决定。

## 13. 纸翼：形状、人体方向、相机方向分开

### 13.1 形状

泳装小南翼形以游戏图1000134912、1000134910及最新校准为依据：肩胛窄根、长内段、由窄渐宽、上拱长弧、外端下垂，矩形薄纸错层搭接。旧短扇翼不能继续作为标准，纸翼也不能变成鸟羽。

### 13.2 方向

翼根和内段随上背部偏航、前倾、侧倾转动，外端允许柔性弯曲和重力下垂；相机视角决定近远翼的透视缩短与遮挡。不能把正面展开的二维翼图贴到每个转身人物背上。

左右对称本身不是错误。正面或特定前倾角度仍可能对称；要检查的是翼根、背部、投影和重力关系，而不是为了“看起来物理正确”强行画成不对称。

### 13.3 起飞与完整取景

`姿势/空中姿势.txt`已把身体悬浮、斜下展开双臂、靠拢双腿及轻屈膝写为独立动作。衣装和纸翼另加，地面投影与双脚空气间隙辅助证明离地。

2026-10-08空中对照实际返回Grok两张、GPT一张，三张都因翼展或构图未通过，不能称为完成标准参考。Grok的宽景尝试即使正文写3:2，仍返回832×1248竖图并裁切右翼。文字里的“宽画幅”不是已经生效的尺寸参数；不能用后期拉伸图片掩盖它。

没有验证当前入口的画幅控制前，不承诺文字一定能生成横图。取景要留足翼尖空间；如果完整翼形是目标，裁掉翼尖就是未通过。

## 14. 返修流程：保留正确部分，记录附带退化

1. 确认正在查看的是用户指出的文件和版本，保存原图快照及哈希。
2. 写一个具体问题，例如“多出的小腿位于左下，属于重复肢体”，而不是只写“修复人体”。
3. 指定编辑对象和标准示例的不同用途，明确应保持的脸、衣装、动作、构图及背景。
4. 对单一问题优先做单一改动；不要在修手时顺带换脸、改衣装和重新设计背景。
5. 候选独立保存，比较全图以及问题局部，检查是否新增缺陷。
6. 只有目标问题已解决且其他应保持部分未明显退化，才标通过并执行已授权的覆盖。
7. 若修好纸花但新增鞋带，仍为待返修；保留局部成功的记录，不宣称完整成功。

“完整图参考编辑”“重新生成新构图”和“蒙版局部编辑”是不同操作，界面和记录应区分。蒙版也不保证未蒙区域逐像素不变；需要核验尺寸对齐、接口的遮罩约定和全图变化。

白鹤足部曾从整图参考编辑逐步尝试局部蒙版，也有接口只返回裁切放大或完全不改变深沟。有效经验是保留正确的连续袜料标准和完整构图验收，而不是假定某一种入口一定更好。

## 15. Grok实际是怎样跟随泳装小南的

### 15.1 本项目已验证的调用方式

近期通过用户授权的老服务商接口调用：

- 地址：`https://sraiapi.com/v1/images/edits`。
- 模型字符串：`grok-imagine`或`grok-imagine-image-quality`。
- 请求方式：JSON正文，包含model、prompt和images。
- images中实际发送参考图字节转换的Base64 data URI，不是只写本地文件路径。
- 本次普通测试按04衣装、01主脸的顺序发送两张图。
- 未另设seed、size、quality或输出格式参数，实际返回默认832×1248。

这是该第三方服务本项目实测的兼容格式，不是所有Grok或其他Images API都使用相同结构，也不独立证明底层路由、模型版本或内部处理。

```json
{
  "model": "grok-imagine-image-quality",
  "prompt": "<实际完整提示词>",
  "images": [
    {"type": "image_url", "url": "data:image/png;base64,<参考04图片字节>"},
    {"type": "image_url", "url": "data:image/png;base64,<参考01图片字节>"}
  ]
}
```

中文注释：示例展示本次第三方接口的结构；尖括号为占位符，真正发送时填入完整提示词和图片数据。密钥通过已保存的凭据读取，不放在文档或请求记录中。

### 15.2 实际使用过的身份开头

```text
One realistic photograph of the SAME fictional adult Chinese cosplayer, age 26. Image 1 defines her exact white halter one-piece swimsuit, purple hairstyle and shoes. Image 2 defines her face. Preserve her adult identity and outfit.
```

中文注释：同一位26岁成年中国虚构coser，参考1指定白色挂脖连体泳装、紫发和鞋，参考2指定面孔；保持身份与衣装。

之后追加目标姿势、场景和适用质量模块。真正让它跟随角色的是参考输入与明确分工，角色名字只是语义提示，不能代替图像身份锚点。

### 15.3 模型选择是暂定的

初次同条件普通站姿比较，两档差距不大，普通档略快；后续带翼和坐姿样本中quality有局部较好表现，最近批次暂选quality。不能把这个选择写成quality全面更强。

记录时两档成功输出均为每张0.12美元；这是当时该服务商的观测价格，不是模型名称自带的永久价格。列表中出现的grok-imagine-image-2.0曾在编辑端点返回模型不存在，不能仅凭列表就宣称可用。

带翼四、五参考请求曾502，三参考配置可成功；减少的是辅助参考并同步图片编号，不偷偷降低动作要求。此现象不证明硬上限一定是三张，也不证明502一定由参考数量造成。

## 16. 内置GPT、第三方API和本地训练分开记录

内置图像工具、老接口原生/超分配置、新接口和Grok配置都是不同调用入口。每张图记录实际入口，不根据用户希望的顺序推测“这张应该用了哪个”。服务商所谓原生、超分是其配置称呼，不能推断成官方统一档位。

图像通过本地脚本或界面调用API，需要该服务商的凭据和计费；对话中的内置图像工具另外记录，不把两种使用量合并成本。文档和日志不保存明文key、账号令牌或Authorization。

参考图在请求里是否真正上传，必须由实际参数、参考快照和哈希确认。提示词写“参考此路径”不会自动让远端服务访问本机文件。

本项目兼容程序把质量约束追加到实际prompt，未在近期Grok比较中验证独立negative_prompt是否支持或有效。`质量约束nagetive`是用户指定的目录名，不代表所有调用都有一个可用的负面参数。

正向先说明要保留的结构和材料，再列少量针对性排除。相比无限重复“坏手、坏脚”，写清每只手的连接、掌心方向、接触对象，以及袜料如何连续包覆，更便于生成和验收；但本项目没有证明它能消除所有错误。

## 19. 错误分类、重试与成本

| 情况 | 应记录为什么 | 不应直接推断为什么 |
|---|---|---|
| 502、524、连接超时 | 网关、服务或传输错误；保存状态与阶段 | 一定是提示词违规或模型不会画 |
| API_KEY_DISABLED | 凭据被服务端禁用 | 角色或衣装不合格 |
| 模型不存在 | 当前端点与模型配置不可用 | 模型整体不具备生图能力 |
| 明确moderation_blocked | 安全系统拒绝及请求ID、阶段 | 已生成一张待返修图片 |
| 仅failed，无具体原因 | 原因未明，保留上下文 | 自动归为安全拒绝 |
| HTTP成功且返回图片 | 接口完成输出 | 人体、动作和衣装通过 |
| 输出脚部裁切或原图超分 | 返回内容偏离目标 | 已完成完整人物返修 |

连接问题可检查代理、网络和当前配置。本机曾使用127.0.0.1:7890，但不能把开代理当成画质改进，也不能要求每台机器都有同一代理。

技术失败在确认原因后可以有限重试；超时可能无法确认远端是否已完成，应先核对输出和用量，避免重复收费。明确安全拒绝时保存错误并停止，不通过委婉改写、连续抽卡或更换入口规避。

成本优先核对可归因的用量与模型费用记录。曾出现钱包被外部充值，也出现某图前后钱包差0.2000352、模型actual_cost只增加0.12的情况；不能把钱包首尾差全算成该图费用。返修不合格但实际返回了图片，仍可能已经收费。

## 20. 审核、版本、命名和可复现记录

### 20.1 标签

- 刚返回：待审核。
- 经过检查且达到当前任务要求：已通过。
- 发现问题且保留候选：待返修，写具体原因。
- 请求失败没有图片：记录失败与缺项，不虚构一张候选，也不把它算进成图数。

自动评分或脚本可以帮助找重复图、读取尺寸、生成检查拼图、核对文件和提示词对应关系；本项目没有经过验证的脚本能保证识别所有多指、错足、异常关节或身份漂移，仍需看图。

### 20.2 逐图检查顺序

1. 对文件：路径、版本、原图或候选、哈希是否一致。

**Grok API（B02、B03）**：历史使用`POST https://sraiapi.com/v1/images/edits`，`Content-Type: application/json`，Bearer鉴权。提交字段是`model`、`prompt`、`images`；每张图的结构为`{"type":"image_url","url":"data:image/png;base64,实际图片编码"}`。不是Chat对话端点，不把图像metadata、图片路径字符串或示例省略号当成实际图片上传。该JSON输入结构是这个第三方接口当时使用的格式，不能直接套到GPT的multipart编辑调用。

下面PowerShell代码以B02重放历史字段；B03只换请求文件。先配置对应Grok渠道的`GROK_IMAGE_API_KEY`。这段代码没有添加size、quality、seed、negative_prompt等原请求未发送的字段。保存响应中的base64图片或URL；不自动把返回图评为已通过。

```powershell
$requestFile = '{project_root}/other/真实请求参考-20261008/B02/请求.json'
$job = Get-Content -Raw -Encoding UTF8 -LiteralPath $requestFile | ConvertFrom-Json
if (-not $env:GROK_IMAGE_API_KEY) { throw '请先配置对应渠道的 GROK_IMAGE_API_KEY' }
$images = @($job.references | ForEach-Object {
  $encoded = [Convert]::ToBase64String([IO.File]::ReadAllBytes($_.frozen_path))
  @{ type = 'image_url'; url = 'data:image/png;base64,' + $encoded }
})
$body = @{ model = $job.recorded_parameters.model; prompt = $job.prompt; images = $images }
$endpoint = $job.recorded_parameters.base_url.TrimEnd('/') + '/' + $job.recorded_parameters.endpoint.TrimStart('/')
$response = Invoke-RestMethod -Method Post -Uri $endpoint `
  -Headers @{ Authorization = 'Bearer ' + $env:GROK_IMAGE_API_KEY } `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes(($body | ConvertTo-Json -Depth 10))) -TimeoutSec 600
$jobDir = Split-Path -Parent $requestFile
$stem = Join-Path $jobDir ('重放-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$response | ConvertTo-Json -Depth 30 | Set-Content -LiteralPath ($stem + '-响应.json') -Encoding UTF8
$i = 0
foreach ($item in $response.data) {
  $i++
  if ($item.b64_json) {
    $bytes = [Convert]::FromBase64String($item.b64_json)
    if ($bytes.Length -lt 8) { throw '返回图片内容过短，请检查响应' }
    $ext = if ($bytes[0] -eq 137 -and $bytes[1] -eq 80) { '.png' } elseif ($bytes[0] -eq 255 -and $bytes[1] -eq 216) { '.jpg' } else { '.bin' }
    [IO.File]::WriteAllBytes(($stem + '-' + $i + $ext), $bytes)
  } elseif ($item.url) {
    $item.url | Set-Content -LiteralPath ($stem + '-' + $i + '-图片URL.txt') -Encoding UTF8
  } else { Write-Warning '此data项没有b64_json或url，请检查保存的响应' }
}
if (-not $response.data) { Write-Warning '响应没有data数组，请检查保存的响应结构' }
```

#### 质量检查与返修：实际约束如何进入请求

A02的脚趾方向与承重、A05的双臂双腿及关节、B02/B03的手指数量、脚趾左右与鞋带数量，已经在上面的实际完整提示词中，不需要再追加一遍。B02/B03的`quality`只是拼入prompt的文字模块，**不是独立negative_prompt参数**。历史未传入单独negative字段；不把软件有“质量约束”输入框理解成服务端一定支持负向提示词参数。

生成后采用独立检查，不让模型在同一张成图中用文字自称通过：

1. 核对主脸、琥珀眼妆、纸玫瑰所在身体右侧、唇钉，以及白色挂脖连体泳装的剪裁和覆盖。自拍时考虑镜像，不简单按画面左右定错。
2. 核对可见手腕与手掌连接、各可辨识手指数目和关节方向；遮挡手指允许不可见，不强迫每只手展示五根。
3. 沿髋—大腿—膝—小腿—踝逐段追踪；检查多余肢体、左右脚拇趾位置、脚趾顺序、鞋底接触与阴影。不能仅凭“没看见多指”证明被遮挡部分完全正确。
4. 鞋为单道横向白色前掌带、紫色底与独立粗跟，不能额外加踝带或第二道脚背带。泳装小南裸足穿鞋，不套用白鹤的白丝袜专用约束。
5. 带纸翼时检查窄根、长弧、矩形纸片和完整翼端。弯腰、侧身和侧拍时，翼根随躯干转动、左右翼投影及遮挡应对应机位，不能机械保持正面镜像对称。这个方向约束来自后续经验，是新请求可选的补充，不是A06/A07当时已提交的全部原文。
6. 记录实际尺寸和可检查范围；近景不评价画外脚趾，半身纸翼图不冒充全身标准。返回图默认待审核；通过后才放正式图集，失败保留具体缺陷。

真实返修提示词已经给出三类：A02校正鞋型、A04移除误带入道具、A07恢复背部带结构。它们共同采用“目标图 + 必要结构参考 + 只改明确缺陷 + 明确保留项”；本节不捏造一条从未实际提交且通过的手指／脚趾返修请求。新的手足问题需要依具体位置写返修指令，再检查是否附带改变脸、衣装、鞋或纸翼。
